PR #2 native discriminated unions — implementation quality is high but the dependency-approval gate is unsatisfied. Single 🔴 blocker is procedural (missing SCA), not technical.

## What this PR delivers

A clean, well-tested implementation of native discriminated unions:
- New `Lambdaba.SourceGenerators` Roslyn IIncrementalGenerator project (netstandard2.0, Microsoft.CodeAnalysis.CSharp 5.3.0, PrivateAssets="all").
- `UnionGenerator` emits per `[Union] partial class`: instance `Match<TResult>`, `bool HasValue`, `bool Is<Case>` per case, `bool TryGetValue(out CaseN?)` overloads, plus a brand-side `Match<A, TResult>(Data<F,A>, …)` when the union's brand class implements one of the five HKT typeclass interfaces.
- Primitive `Union<T1..T8>` arities via the C# 15 `union` keyword.
- `Either<L,R>` migrated from abstract record to `[Union] partial class`; redundant carrier param dropped from cases (`Left<L,R>` → `Left<L>`, `Right<L,R>` → `Right<R>`); nine dead `_ => throw new NotSupportedException()` arms eliminated.
- `MaybeExtensions.Match` renamed to `Fold` (Haskell `maybe def f m`) to disambiguate from the generated case-tagged `Match`. `IsLeft`/`IsRight` removed from `EitherExtensions.cs`; `IsJust`/`IsNothing` removed from `MaybeExtensions.cs` — generator-emitted now.
- ADR-0001 records the decision; spec at `src/Lambdaba.Tests/Specs/UnionGeneratorSpec.cs` (12 tests, locked) is honoured unmodified.
